# The book passport: decisions for a whole book

The passport holds what cannot be decided inside a single chunk and yet must be
decided the same way from beginning to end. Without it every chunk decides again —
and decides differently: the narrator is "I" in chapter three and "he" in chapter
seven, a character is addressed formally in one scene and familiarly in the next.

It is built by one call over the whole book: the model reads the entire text. The
button is in the "Ask the model" card on this page; when there is no passport yet,
that card is the whole of the screen.

## What is in it

**Kind and register.** Fiction or non-fiction, and what register it is written in:
neutral, elevated, colloquial.

**Narration.** Person (first, second, third) and tense (past, present).
Separately, the form of address — the familiar or the formal "you". English does
not make the distinction; a translation into a language that does makes it in
every line of dialogue, and it can only be settled from the book as a whole.

**Author.** Name and gender. Gender matters wherever the target language agrees
with it — and not only in a preface: it colours a narrator's voice when the
narrator stands close to the author.

**Characters.** Who acts, of what gender, and a dossier — what the book says about
them. The dossier reaches the translator along with the chunk that character
appears in, so the briefing differs from scene to scene.

**How direct speech is set.** Which mark opens a line in the target language: a
dash, quotation marks, guillemets. This is **set for the target language before
translating**, not read out of the text — the text does not exist yet.

**The book's description.** Title, the author as spelt in the target language, and
a blurb for the e-reader. They go into the empty fields of the Book page; whatever
you have typed there a rebuild leaves alone. If the model gave the title of a
published translation, the Book page says so — worth checking.

**Notes for the translator.** Whatever else the model thinks a translator of this
book should know: its own markup, recurring devices, traps. You accept or reject
each note; only accepted ones go into every chunk's prompt. You can add your own.
Notes also come from the translation review, by the "Move to the passport" button
on the monitor; those are marked "from the translation review" and, like the
model's own, wait for your decision.

**A note's boundaries.** Sometimes a rule changes in the course of a book: a
character takes a new name and with it a new gender, two people go from formal to
informal address. A note can then be given "from a place…" and "up to a place…":
find the place by searching the original or the translation and press "Pick". The
note goes only into the chunks between its boundaries, and the chunk a boundary
falls inside is told the phrase the rule starts or stops holding at. A rule with
two halves is two notes: the first "up to a place", the second "from a place", the
same place for both. A boundary is kept as a quote from the original, so it
survives the text being cut into chunks again. If the quote is not in the text,
the page warns you, and the note holds for the whole book as if it had no
boundary. The translation review sees the boundaries and can propose its own —
the "Move to the passport" button then carries the note over with them.

**The point-of-view map.** Who narrates each chunk. When there are several
narrators, a separate whole-book call sits under the map: the model reads the book
through and quotes the start of each stretch, and the program checks that every
quote occurs in the text exactly once. While nothing is translated, the text is
re-split on these boundaries so that no chunk is shared by two narrators. The call
can be repeated. Until there is a map, the translator is told to avoid gendered
forms around the narrator. Maps counted earlier from names in dialogue are no
longer used — for such books, ask for the boundaries again.

## Editing by hand

All of it can be corrected on this page. The model reads a book well but gets
things wrong — particularly the gender of minor characters and the form of
address.

Before rebuilding the passport, the previous one is set aside as a backup: hand
edits do not vanish quietly.

## The second route

Like the other whole-book calls, this one has "Build prompt" beside its button —
for a web console, where the window is bigger and no API key is needed. The answer
is pasted back and goes through the same checks.

## When to build it

Before translating. A passport built afterwards corrects nothing in the finished
text — the translator read the one that existed while it was working.

## What next

With a passport in place, go back to the monitor and run the translation.
